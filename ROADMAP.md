## Later

| Idea | Why it isn't in 1.1 |
|---|---|
| A50 X, A50 Gen 4 | Different protocols / USB ids (Gen 4 is VID 9886; the A50 X uses a newer protocol). Not on this PC, so not testable. |
| Is the A50 switched on? | The Gen 5 base station answers the battery GET either way; HeadsetControl documents no "headset connected" read. |
| Bluetooth charging state | Neither Windows' battery property nor LE Battery Level reports it. The newer Battery Level Status characteristic (0x2BED) could, on the few devices that have it. |
| Bluetooth notifications on devices Windows doesn't subscribe to | Enabling them means writing the device's CCCD - a write, which Hallow Gear doesn't do. Those devices are read every 5 min instead. |
| Battery from G HUB's local websocket | Undocumented; HID++ already gives the mouse directly and the A50 has its own documented GET. |
| Other brands' dongles (Razer, SteelSeries, Corsair...) | Each has its own protocol; HeadsetControl documents several headsets - a later version could add their battery GETs the same way. (Their Bluetooth modes already work if they report battery to Windows.) |
| Hallow Remote / phone view | Remote 1.18 shows status.json's devices; 1.2.2 added the `refresh` pipe and opaque device ids for it. |
